This page provides a list of the FHIR artifacts defined as part of this implementation guide.

Behavior: Capability Statements

The following artifacts define the specific capabilities that different types of systems are expected to have in order to comply with this implementation guide. Systems conforming to this implementation guide are expected to declare conformance to one or more of the following capability statements.

Capacités serveur FHIR pour l'IG Preadmission

Décrit les capacités d’un serveur FHIR conforme à l’IG de préadmission hospitalière en France.

Behavior: Search Parameters

These define the properties by which a RESTful server can be searched. They can also be used for sorting and including related resources.

Encounter Preadmission Status SearchParameter

Recherche des encounters par statut de pré-admission (extension PreadmissionStatutFr).

Terminology: Value Sets

These define sets of codes used by systems conforming to this implementation guide.

preadmission-consent-category-vs

ValueSet pour les catégories de consentement. Tous les codes sont standards et existants.
preadmission-consent-code-vs

Code HL7 représentant les types d’action concernées par le consentement. Tous les codes sont standards et existants.
preadmission-consent-purpose-reason-vs

Raisons justifiant l’utilisation des données personnelles (HL7 v3 ActReason).
preadmission-document-type-vs

Liste des types de documents autorisés pour la préadmission
preadmission-status-vs

Statuts valides qu’une préadmission peut prendre.
type-couverture-sociale-vs

Restreint les types de couverture à PUBLICPOL (AMO) et EHCPOL (AMC)
type-venue-encounter-vs

Les différents types d’admission (hospitalisation, consultation, etc.)
